I. Git és GitHub – ismétlés

1. Git-repository létrehozása

Platform: Debian VM – SSH terminál (helyi PowerShell vagy VS Code terminálból kapcsolódva).

Hozz létre egy container-lab mappát, és inicializálj benne main alapágú Git-repositoryt.

Segítség: mkdir, cd, git init -b main, git status.

NoteHa hiányoztál a korábbi Git-gyakorlatról

Először ellenőrizd, hogy telepítve van-e a Git:

git --version

Ha a parancs hibát jelez (például command not found), telepítsd a Gitet Debianon:

sudo apt update
sudo apt install -y git

A commitokhoz állítsd be a saját nevedet és e-mail-címedet:

git config --global user.name "Hallgato Neve"
git config --global user.email "hallgato@example.com"

A példában szereplő nevet és e-mail-címet cseréld a saját adataidra. Ellenőrzés: git config --global --list.

2. Első commit és ágak

Platform: Debian VM – SSH terminál; fájlszerkesztéshez nano vagy jed.

Készíts proba.txt fájlt Hello World tartalommal. Add a staging area-hoz, majd készíts first commit üzenetű commitot. A Dev és Test ágakat a következő feladatban hozd létre.

Segítség: nano proba.txt vagy jed proba.txt, git add, git commit -m, git log --oneline.

3. Merge-konfliktus

Platform: Debian VM – SSH terminál; szerkesztéshez nano vagy jed.

Hozd létre a Dev és Test ágakat a main ágból. A Dev ágon írd át a proba.txt első sorát Hello from Dev szövegre, és commitold. A Test ágon ugyanezt a sort írd át Hello from Test szövegre, és commitold. Válts vissza a main ágra, olvaszd be a Dev, majd a Test ágat. A konfliktust úgy oldd fel, hogy a végső fájlban a Dev-változat maradjon.

Segítség: git switch, git merge, git status, cat proba.txt, git add, git commit. Konfliktusnál szerkeszd ki a <<<<<<<, =======, >>>>>>> jelöléseket.

AI-segítség megengedett: A merge-konfliktus értelmezéséhez és feloldásához. A megoldást saját repositorydban ellenőrizd.

4. GitHub remote és push

Platform: GitHub – helyi böngésző; Git-parancsok: Debian VM SSH terminál.

Használd a múlt heti GitHub-repositorydat. A mostani container-lab külön helyi Git-repository, ezért itt is be kell állítani az origin remote-ot. A mostani munkát a GitHubon új, container-lab nevű ágra töltsd fel, a korábbi main ág felülírása nélkül.

Segítség: git remote add origin <repository-URL>, git remote -v, git push -u origin main:container-lab. A main:container-lab a helyi main ágat a távoli container-lab ágra tölti fel.

NoteHa nem voltál a múlt heti GitHub-gyakorlaton

Hozz létre egy új, üres GitHub-repositoryt (README, .gitignore és licenc nélkül). Állítsd be az origin remote-ot, majd töltsd fel a helyi main ágat a git push -u origin main paranccsal. HTTPS esetén megfelelő GitHub-hitelesítés, SSH esetén beállított SSH-kulcs szükséges.

II. Docker – öt alapfeladat

5. Docker Engine telepítése

Platform: Debian 11, 12 vagy 13 VM – SSH terminál, sudo jogosultsággal.

Ellenőrizd a Debian verzióját, majd telepítsd a Docker Engine-t a Debian saját csomagtárából. A Docker Compose telepítésével csak a 10. feladatban foglalkozunk.

cat /etc/os-release
sudo apt update
sudo apt install -y docker.io
sudo systemctl enable --now docker

Ellenőrzés:

sudo systemctl is-active docker
sudo docker version

6. Első konténer: Hello World

Platform: Debian VM – SSH terminál.

Indíts egy konténert a hivatalos hello-world image-ből. A teljes parancsot magad állítsd össze.

Segítség: docker, run, hello-world; a --rm kapcsolóval a konténer futás után automatikusan törölhető. Szükség lehet sudo használatára. További támpont: docker run --help.

7. Image-ek és konténerek kezelése

Platform: Debian VM – SSH terminál.

Végezd el a következő négy műveletet:

  1. Listázd a helyben elérhető Docker-image-eket.
  2. Indíts egy alpine-test nevű konténert az alpine:3.20 image-ből, amely kiírja: Container OK. Itt ne használj --rm kapcsolót.
  3. Listázd az összes konténert, a leállítottakat is.
  4. Töröld az alpine-test konténert.

Segítség: docker images, docker run, docker ps, docker rm; kapcsolók: --name, -a. A teljes parancsokat önállóan állítsd össze.

8. Nginx és portleképezés

Platform: Debian VM – SSH terminál; HTTP-ellenőrzés a VM-en curl segítségével.

Indíts Nginx webszervert háttérben, web-test néven. A Debian VM 8080-as portját rendeld a konténer 80-as portjához. Ellenőrizd a HTTP-választ, listázd a futó konténert, majd állítsd le és töröld. Az öt parancsot magad egészítsd ki.

Segítség: docker run, docker ps, docker stop, docker rm, curl -I; kapcsolók: -d, --name, -p HOST:CONTAINER. A HTTP-ellenőrzés a VM-en történik, ezért nincs szükség Azure NSG-portnyitásra.

TipSegítség: HTTP-ellenőrzés a curl paranccsal

A curl terminálból küld HTTP-kérést. A -I kapcsoló csak a válasz fejléceit jeleníti meg. Példa: curl -I http://localhost:8080. Sikeres Nginx-válasznál általában HTTP/1.1 200 OK látható. Ha nincs telepítve: sudo apt install -y curl.

9. Saját Dockerfile és image

Platform: Debian VM – SSH terminál; fájlok szerkesztése nano vagy jed segítségével.

Hozz létre ugyanabban a mappában egy report.sh és egy Dockerfile nevű fájlt. Az alábbi kódokat használhatod.

report.sh:

#!/bin/sh
echo "CONTAINER REPORT"
echo "Hostname: $(hostname)"
echo "Date: $(date)"

Dockerfile:

FROM alpine:3.20
WORKDIR /app
COPY report.sh .
CMD ["sh", "report.sh"]

Önálló feladat: állítsd össze a docker build parancsot, amely az aktuális könyvtárból report-image:v1 nevű image-et készít.

Segítség: docker build, -t (név és címke), . (aktuális könyvtár mint buildkontextus); docker build --help.

Az elkészült image futtatásához használd:

sudo docker run --rm report-image:v1

AI-segítség megengedett: A Dockerfile ellenőrzéséhez és hibák értelmezéséhez. A javaslatot saját futtatással ellenőrizd.

III. Docker Compose – első projekt

10. Docker Compose telepítése

Platform: Debian 11/12/13 VM – SSH terminál. A Docker Engine már működik az 5. feladat óta.

Telepítsd a Docker Compose v2 CLI-plugint. A következő, x86-64 architektúrájú Debian VM-en kipróbált telepítési lépéseket használd. A VM architektúráját az uname -m paranccsal ellenőrizheted; eltérő architektúrán más bináris szükséges.

sudo apt install -y curl
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -fSL \
  https://github.com/docker/compose/releases/download/v2.40.3/docker-compose-linux-x86_64 \
  -o /usr/local/lib/docker/cli-plugins/docker-compose
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose

Ellenőrizd a telepített Compose verzióját:

sudo docker compose version

11. Első Compose-projekt – Nginx

Platform: Debian VM – SSH terminál; fájlszerkesztés nano vagy jed segítségével.

Hozd létre a ~/compose-project könyvtárat, majd abban a compose.yaml fájlt:

mkdir -p ~/compose-project
cd ~/compose-project
nano compose.yaml

A fájl tartalma:

services:
  web:
    image: nginx:stable
    ports:
      - "8081:80"

Önállóan állítsd össze a következő négy parancsot: ellenőrizd a Compose-konfigurációt, indítsd el háttérben a projektet, listázd a projekt konténereit, majd curl segítségével ellenőrizd a HTTP-választ a VM 8081-es portján.

Segítség: docker compose config, docker compose up, docker compose ps, curl -I; a háttérben futtatáshoz -d kapcsoló kell. A projektet hagyd futva a feladat végén; a 12. feladat ettől független, külön könyvtárban készül.

IV. Második Compose-projekt – PHP/Apache és MariaDB

A 12–15. feladatban egy egyszerű feladatnyilvántartó webalkalmazást indítasz két konténerben: a PHP-t futtató Apache webszerver és a MariaDB adatbázis külön szolgáltatás. A forrásfájlokat készen kapod; a hangsúly a Linux-fájlkezelésen, a Compose-parancsokon, a szolgáltatások ellenőrzésén és a tartós adattároláson van. A projekt a korábbi Nginx Compose-projekttől független.

WarningErőforrások és oktatási jelszavak

A projektet kis memóriájú VM-hez igazítottuk, de 0,5–1 GB RAM esetén lassulás vagy memóriahiány előfordulhat. Ha a Docker nem válaszol, jelezd az oktatónak. A mintajelszavak kizárólag elkülönített oktatási környezetben használhatók; éles szolgáltatásban titokkezelést alkalmaznánk. A 8082-es portot csak a saját IP-címed számára nyisd meg, és a teszt után zárd le.

12. A projektkönyvtár és a fájlok előkészítése

Platform: Debian VM – SSH terminál; nano vagy jed.

Hozd létre a ~/php-mariadb-project könyvtárat, lépj bele, majd az alábbi tartalmak alapján készítsd el a compose.yaml, Dockerfile, init.sql, index.php fájlokat. A fájlokat nano vagy jed szerkesztővel hozd létre. Végül listázd a könyvtár fájljait, és ellenőrizd egy kiválasztott fájl tartalmát.

compose.yaml

services:
  db:
    image: mariadb:11.4
    restart: "no"
    command:
      - --innodb-buffer-pool-size=32M
      - --max-connections=20
      - --performance-schema=OFF
    environment:
      MARIADB_ROOT_PASSWORD: root_demo_password
      MARIADB_DATABASE: taskdb
      MARIADB_USER: taskuser
      MARIADB_PASSWORD: task_demo_password
    volumes:
      - db_data:/var/lib/mysql
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 30s

  web:
    build: .
    restart: "no"
    depends_on:
      db:
        condition: service_healthy
    ports:
      - "8082:80"
    environment:
      DB_HOST: db
      DB_NAME: taskdb
      DB_USER: taskuser
      DB_PASSWORD: task_demo_password

volumes:
  db_data:

Dockerfile

FROM php:8.3-apache
RUN docker-php-ext-install pdo_mysql
COPY index.php /var/www/html/index.php

init.sql

CREATE TABLE IF NOT EXISTS tasks (
    id INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

index.php

<?php
$host = getenv('DB_HOST');
$dbname = getenv('DB_NAME');
$user = getenv('DB_USER');
$password = getenv('DB_PASSWORD');

try {
    $pdo = new PDO(
        "mysql:host=$host;dbname=$dbname;charset=utf8mb4",
        $user,
        $password,
        [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
    );
} catch (PDOException $e) {
    http_response_code(503);
    exit("Adatbazis-kapcsolati hiba. Ellenorizd a MariaDB kontenert.");
}

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $title = trim($_POST['title'] ?? '');
    if ($title !== '') {
        $stmt = $pdo->prepare("INSERT INTO tasks (title) VALUES (?)");
        $stmt->execute([$title]);
    }
    header('Location: /');
    exit;
}

$tasks = $pdo->query(
    "SELECT id, title, created_at FROM tasks ORDER BY id DESC"
)->fetchAll(PDO::FETCH_ASSOC);

14. A feladatnyilvántartó kipróbálása

Platform: Debian VM – terminál és böngésző.

Ellenőrizd a HTTP-választ a VM-en a curl -I http://localhost:8082 paranccsal. Ezután nyisd meg a webalkalmazást a böngészőben. Azure VM esetén az elérési cím http://<VM-publikus-IP>:8082; a 8082/TCP bejövő portot az Azure NSG-ben szükség esetén csak a saját IP-címedről engedélyezd. Hozz létre legalább három, általad választott című feladatot, majd frissítsd az oldalt, és ellenőrizd, hogy megjelennek-e.

Beadandó: a HTTP-ellenőrzés parancsa és státuszsora, a böngészőben használt teljes URL, valamint a három ténylegesen rögzített feladat címe. Képernyőkép nem szükséges.
