3. hét – Folyamatok, teljesítmény és Azure monitoring

VS Code → Azure PowerShell → Guest OS → Get-Counter → AI → Resource Graph

A harmadik heti gyakorlaton a Visual Studio Code és az Azure PowerShell segítségével elindítjuk és ellenőrizzük a saját Azure VM-et, majd a virtuális gép operációs rendszerében folyamatokat és CPU-terhelést vizsgálunk. Ezután egy egyszerű monitorozó scriptet készítünk AI segítségével, végül az Azure-erőforrásokat Azure Resource Graph lekérdezéssel vizsgáljuk meg.

ImportantHogyan használd?

A feladatokat sorrendben végezd el. A válaszmezők tartalmát a böngésző ezen a gépen automatikusan megőrzi.

A gyakorlat végén add meg a Neptun-kódodat, majd válaszd a Beadás gombot. Jelszót, Training Key-t vagy más hitelesítési adatot ne írj a munkafüzetbe.

A Neptun-kód 6 betűből és/vagy számjegyből áll.

I. Azure VM és Guest OS – VS Code / PowerShell

NoteKét megfigyelési szint

Az 1. és 5. feladatban az Azure-erőforrást vizsgáljuk a VS Code PowerShell termináljából. A 2–4. feladatban a virtuális gép Windows operációs rendszerében dolgozunk. Ez ugyanaz a két nézőpont, amelyet az előadáson is megkülönböztettünk: Azure platform és Guest OS.

1. feladat – A virtuális gép elindítása és az indítás ellenőrzése

Nyisd meg a Visual Studio Code alkalmazást, majd egy PowerShell terminált. Jelentkezz be az Azure-ba, és válaszd ki a gyakorlaton használt előfizetést.

A korábban tanult Start-AzVM paranccsal indítsd el a saját virtuális gépedet. A parancsban a saját erőforráscsoportod és VM-ed nevét használd.

Vizsgáld meg a parancs kimenetét. Az indítás sikerességét a Status mező jelzi, a StartTime és EndTime pedig az indítási művelet időadatait mutatja.

2. feladat – Folyamatok és az EXE fájlok helye

Kapcsolódj RDP-vel a saját Azure VM-edhez, majd indíts Windows PowerShellt.

A Get-Process segítségével listázd a futó folyamatokat. A sok találat miatt:

  1. csak azok a folyamatok maradjanak, amelyeknél a Path értéke nem üres;
  2. csak az első 10 találatot jelenítsd meg;
  3. a kimenetben a Name, Id és Path mezők szerepeljenek.
TipSegítség a szűréshez

A nem üres Path értékek szűréséhez ezt a pipeline-elemet használhatod:

Where-Object { $_.Path }

Az első 10 találat kiválasztásához a korábban megismert Select-Object parancs -First paraméterét használd.

Válassz a megjelenített 10 folyamatból egy folyamatot, és add meg az adatait.

NoteMiért érdekes a fájl helye?

Egy ismeretlen vagy gyanús folyamat vizsgálatakor az EXE fájl helye hasznos információ lehet. A fájl elérési útja azonban önmagában nem bizonyítja, hogy egy program biztonságos vagy kártékony.

3. feladat – CPU-terhelés mérése Get-Counter segítségével

A Get-Counter PowerShell-paranccsal a Windows teljesítményszámlálóit kérdezheted le. Most a processzor kihasználtságát fogod megmérni.

A processzorhoz tartozó számlálócsoport neve magyar Windows esetén Processzor, angol Windows esetén Processor. Listázd ki a csoporthoz tartozó számlálókat. Magyar Windows esetén például:

(Get-Counter -ListSet 'Processzor').Paths

Keresd meg a CPU kihasználtságát (%) mutató számlálót. A listában a számláló útvonalában (*) szerepelhet. A teljes rendszer összesített CPU-terhelésének méréséhez a * helyett használd a _Total példányt.

Készíts 5 mérést 2 másodperces időközzel.

TipSegítség

Több egymást követő méréshez a következő paramétereket használd:

-SampleInterval 2 -MaxSamples 5

4. feladat – Paraméterezhető CPU-monitorozó script AI segítségével

Készíts egy új PowerShell scriptet a VS Code-ban:

  1. válaszd a File → New Text File lehetőséget;
  2. mentsd el a fájlt cpu-monitor.ps1 néven;
  3. ellenőrizd, hogy a VS Code terminálja PowerShellt használ.

Ezután kérj segítséget egy általad választott generatív AI-eszköztől a script elkészítéséhez.

A script követelményei:

  • a futtatáskor Threshold paraméterként kapja meg a CPU-terhelés küszöbértékét;
  • a 3. feladatban megismert Get-Counter segítségével mérje meg az aktuális CPU-kihasználtságot;
  • ha a CPU-terhelés nagyobb a megadott küszöbértéknél, jelenítsen meg piros HIGH CPU üzenetet;
  • egyébként jelenítsen meg zöld CPU OK üzenetet;
  • az üzenet tartalmazza a mért CPU-terhelést és a megadott küszöbértéket is.

A scriptet például így futtathatod:

.\cpu-monitor.ps1 -Threshold 50
ImportantTeszteld mindkét ágat!

A script tartalmát a teszteléshez ne módosítsd. Futtasd különböző Threshold paraméterekkel úgy, hogy egyszer CPU OK, egyszer pedig HIGH CPU eredményt kapj. Ehhez nem szükséges mesterségesen terhelni a CPU-t: a futtatáskor megadott küszöbértéket változtasd.

NoteAI használata

Az AI által generált kódot futtatás előtt olvasd át. Csak olyan parancsot futtass, amelynek érted a célját. Ha szükséges, módosítsd az AI első megoldását.

5. feladat – Azure-erőforrások vizsgálata Resource Graph segítségével

Térj vissza a VS Code PowerShell termináljához. Az Azure Resource Graph segítségével az előfizetésed erőforrásait lekérdezhető adatokként vizsgálhatod.

Ellenőrizd, hogy a Search-AzGraph cmdlet elérhető-e:

Get-Command Search-AzGraph
TipHa a Search-AzGraph parancs nem érhető el

Telepítsd az Az.ResourceGraph modult a saját felhasználói profilodhoz:

Install-Module -Name Az.ResourceGraph -Scope CurrentUser

Ezután töltsd be a modult:

Import-Module Az.ResourceGraph

Végül ellenőrizd újra, hogy a parancs elérhető-e:

Get-Command Search-AzGraph

Ezután kérj segítséget egy generatív AI-eszköztől olyan Search-AzGraph lekérdezés elkészítéséhez, amely:

  • kilistázza az Azure-erőforrásaidat;
  • megjeleníti a name, type, resourceGroup és location adatokat;
  • az eredményt erőforrástípus szerint rendezi.

Futtasd és ellenőrizd a lekérdezést. Ezután módosítsd vagy egészítsd ki AI segítségével úgy, hogy erőforrástípusonként számolja össze az erőforrásokat, és a legtöbb előfordulástól a legkevesebb felé rendezze az eredményt.

NoteMiért érdekes?

Bár csak egy virtuális gépet hoztál létre, az Azure-ban ehhez több kapcsolódó erőforrás is tartozhat, például lemez, hálózati interfész, virtuális hálózat vagy nyilvános IP-cím. A Resource Graph segítségével ezeket egyetlen lekérdezésben áttekintheted.

6. feladat – Az RDP-kapcsolat ellenőrzése

Mielőtt távoli asztallal csatlakozol a virtuális géphez, ellenőrizd a VS Code PowerShell termináljából, hogy a VM RDP-szolgáltatása hálózaton keresztül elérhető-e.

Keresd meg a virtuális géped nyilvános IP-címét a korábban megismert Azure PowerShell-parancsok segítségével, majd ellenőrizd a 3389-es TCP-portot:

Test-NetConnection <PUBLIC-IP> -Port 3389

A <PUBLIC-IP> helyére a saját virtuális géped nyilvános IP-címét írd. A kimenetben keresd meg a RemoteAddress és TcpTestSucceeded értékeket.

WarningHa a TcpTestSucceeded értéke False

Ellenőrizd, hogy a virtuális gép fut-e, helyes nyilvános IP-címet adtál-e meg, illetve hogy az Azure hálózati beállításai engedélyezik-e az RDP-kapcsolatot a TCP/3389 porton.

Ha a TcpTestSucceeded értéke True, indítsd el a Távoli asztali kapcsolat (Remote Desktop Connection) alkalmazást, és csatlakozz a virtuális gépedhez.

ImportantA következő feladatok helye

A 7–10. feladatot már az RDP-vel elért virtuális gépen, a Windows PowerShellben hajtsd végre.

7. feladat – A Guest OS adatainak vizsgálata

Nyisd meg a Windows PowerShellt a távoli gépen, majd kérdezd le a rendszer alapvető adatait:

Get-ComputerInfo

A parancs sok adatot jelenít meg. Pipeline és Select-Object segítségével szűkítsd a kimenetet az alábbi tulajdonságokra:

  • CsName
  • WindowsProductName
  • WindowsVersion
  • OsArchitecture

8. feladat – Mit lát a Guest OS a processzorból?

Vizsgáld meg, milyen processzort és hány feldolgozási egységet lát a Windows!

Kérdezd le a Win32_Processor CIM-osztály adatait, és az eredményt mentsd egy $cpu változóba. Ezután a változó felhasználásával jelenítsd meg az alábbi tulajdonságokat:

  • Name
  • NumberOfCores
  • NumberOfLogicalProcessors

Az eredményt táblázatos formában jelenítsd meg.

TipSegítség

A feladat megoldásához a korábban megismert Get-CimInstance, Select-Object és Format-Table parancsokat használd. A CIM-osztály neve: Win32_Processor.

9. feladat – Folyamatok, erőforrás-használat és szálak

Listázd a futó folyamatokat, majd:

  1. rendezd őket a felhasznált memória alapján csökkenő sorrendbe;
  2. jelenítsd meg csak az első 10 folyamatot;
  3. a listában jelenjen meg a folyamat neve, PID-je és memóriahasználata;
  4. az eredményt táblázatos formában jelenítsd meg.
TipSegítség

Használd a korábban megismert Get-Process, Sort-Object, Select-Object -First és Format-Table lehetőségeket. A memóriahasználathoz a WorkingSet tulajdonságot használhatod.

Válassz ki egy folyamatot a saját Top 10 listádból, és mentsd el egy $p változóba. Ezután a változó segítségével vizsgáld meg a folyamathoz tartozó szálakat, és határozd meg a szálak számát.

TipSegítség

Egy folyamat név szerinti lekéréséhez használhatod a Get-Process -Name paraméterét. A processzhez tartozó szálakat a Threads tulajdonságon keresztül érheted el; a darabszám meghatározásához a Count tulajdonság használható.

10. feladat – Szolgáltatás állapotának ellenőrzése elágazással

Listázd a Windows szolgáltatásait:

Get-Service

Válassz ki egy tetszőleges szolgáltatást, kérdezd le név alapján, majd az eredményt mentsd egy $service változóba.

TipSegítség

A szolgáltatás név szerinti lekéréséhez használd a Get-Service parancs -Name paraméterét.

Ezután készíts egy egyszerű feltételes elágazást, amely megvizsgálja a $service.Status értékét:

  • ha a szolgáltatás állapota Running, jelenjen meg: A szolgáltatás fut.
  • egyébként jelenjen meg: A szolgáltatás nem fut.

Az if/else szerkezet általános alakja:

if (feltétel) {
    # utasítások
}
else {
    # utasítások
}

A konkrét feltételt neked kell megfogalmaznod.
