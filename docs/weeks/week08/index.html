I. Git és GitHub – ismétlés

1. Git konfiguráció és repository

Platform: Debian VM – SSH terminál (helyi PowerShell vagy VS Code terminálból kapcsolódva).

Ellenőrizd a Git telepítését és a commitokhoz beállított nevet, e-mail-címet. Hozz létre egy container-lab mappát, és inicializálj benne main alapágú Git-repositoryt.

Segítség: git --version, git config --get user.name, git config --get user.email, git init -b main, git status. Ha a név/e-mail hiányzik, a git config --global user.name "..." és git config --global user.email "..." parancsokkal állíthatod be.

2. Első commit és ágak

Platform: Debian VM – SSH terminál; szerkesztéshez opcionálisan VS Code Remote-SSH.

Készíts proba.txt fájlt Hello World tartalommal. Add a staging area-hoz, készíts first commit üzenetű commitot, majd hozz létre Dev és Test ágat.

Segítség: printf, git add, git commit -m, git branch, git log --oneline --all --decorate.

3. Merge-konfliktus

Platform: Debian VM – SSH terminál; szövegszerkesztő vagy VS Code Remote-SSH.

A Dev ágon írd át a proba.txt első sorát Hello from Dev szövegre, és commitold. A Test ágon ugyanezt a sort írd át Hello from Test szövegre, és commitold. Válts vissza a main ágra, olvaszd be a Dev, majd a Test ágat. A konfliktust úgy oldd fel, hogy a végső fájlban a Dev-változat maradjon.

Segítség: git switch, git merge, git status, cat proba.txt, git add, git commit. Konfliktusnál szerkeszd ki a <<<<<<<, =======, >>>>>>> jelöléseket.

AI használható: A konfliktus okának értelmezéséhez és a feloldási lépések ellenőrzéséhez. A javaslatot a saját repositorydban ellenőrizd; a beadandóban egy mondatban jelezd, miben segített az AI.

4. GitHub remote és push

Platform: GitHub – helyi böngésző; Git-parancsok: Debian VM SSH terminál.

Hozz létre a GitHubon egy üres, README nélküli repositoryt. Kösd hozzá a lokális repositoryhoz origin néven, majd töltsd fel a main ágat.

Segítség: git remote add origin <repository-URL>, git remote -v, git push -u origin main. HTTPS használatakor GitHub-jelszó helyett megfelelő hitelesítési módszer (például Git Credential Manager vagy token), SSH esetén beállított SSH-kulcs szükséges.

II. Docker – öt alapfeladat

5. Docker Engine és Compose telepítése Debian 12-re

Platform: Debian 12 VM – SSH terminál, sudo jogosultsággal.

Telepítsd a Docker Engine-t és a Compose plugint a Docker hivatalos APT-csomagtárából. Az alábbi parancsok Debian 12 (bookworm) rendszerhez készültek.

sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<'EOF_DOCKER'
Types: deb
URIs: https://download.docker.com/linux/debian
Suites: bookworm
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOF_DOCKER

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker --version
sudo docker compose version

Megjegyzés: Ha a gépen korábban docker.io vagy más, ütköző Docker-csomag szerepel, a telepítés előtt a hivatalos útmutató szerint távolítsd el az ütköző csomagokat. Forrás: https://docs.docker.com/engine/install/debian/

6. Első konténer: Hello World

Platform: Debian VM – SSH terminál.

Futtasd a hello-world image-et. Figyeld meg, hogy a konténer a kiírás után automatikusan leáll.

sudo docker run --rm hello-world

Segítség: docker run konténert indít; a --rm eltávolítja a leállt konténert.

7. Image-ek és konténerek kezelése

Platform: Debian VM – SSH terminál.

Listázd a helyi image-eket. Ezután indíts egy alpine:3.20 konténert, amely kiírja a Container OK szöveget. Most ne használd a --rm kapcsolót. Listázd a futó és a leállt konténereket, végül töröld a leállt Alpine-konténert.

Segítség: sudo docker images, sudo docker run --name alpine-test alpine:3.20 echo 'Container OK', sudo docker ps, sudo docker ps -a, sudo docker rm alpine-test.

8. Nginx és portleképezés

Platform: Debian VM – SSH terminál; HTTP-ellenőrzés curl-lel a VM-en.

Indíts Nginx webszervert háttérben, web-test néven. A Debian VM 8080-as portját rendeld a konténer 80-as portjához. Ellenőrizd a weboldalt a VM-en, majd állítsd le és töröld a konténert.

sudo docker run -d --name web-test -p 8080:80 nginx:stable
curl -I http://localhost:8080
sudo docker ps
sudo docker stop web-test
sudo docker rm web-test

Segítség: -d = háttérben futás; --name = konténernév; -p HOST:CONTAINER = portleképezés. Külső böngészős eléréshez az Azure VM hálózati szabályainak is engedniük kell a 8080-as portot; ezt a feladat nem követeli meg.

9. Saját Dockerfile és image

Platform: Debian VM – SSH terminál; Dockerfile és shell script szerkesztése helyben vagy VS Code Remote-SSH-val.

Hozz létre egy report.sh fájlt és Dockerfile-t. Építs belőlük project-report:1.0 nevű image-et, majd futtasd.

report.sh:

#!/bin/sh
printf 'PROJECT STATUS REPORT\n'
printf 'Hostname: %s\n' "$(hostname)"
printf 'User: %s\n' "$(whoami)"
printf 'Date: %s\n' "$(date)"
printf 'Uptime: %s\n' "$(uptime)"

Dockerfile (ugyanabban a mappában):

FROM alpine:3.20
RUN apk add --no-cache coreutils
WORKDIR /app
COPY report.sh /app/report.sh
CMD ["sh", "/app/report.sh"]

Futtatás:

sudo docker build -t project-report:1.0 .
sudo docker run --rm project-report:1.0
sudo docker images

Segítség: -t = image neve és címkéje; a . a build context aktuális mappája. A szkript POSIX sh-t használ, ezért nem kell külön Bash-t telepíteni.

AI használható: A Dockerfile utasításainak megértéséhez vagy egy kisebb fejlesztés javaslatához. A javaslatot csak kipróbálás és ellenőrzés után alkalmazd.

III. Docker Compose

10. Compose-projekt létrehozása

Platform: Debian VM – SSH terminál; compose.yaml szerkesztése helyben vagy VS Code Remote-SSH-val.

Készíts compose-lab mappát és benne az alábbi compose.yaml fájlt. Két külön Nginx-szolgáltatást indítunk eltérő host portokon.

services:
  web1:
    image: nginx:stable
    ports:
      - "8081:80"
  web2:
    image: nginx:stable
    ports:
      - "8082:80"

Segítség: A services az alkalmazás szolgáltatásait sorolja fel; a ports a host és a konténer portjait rendeli egymáshoz.

AI használható: YAML-szintaktikai hibák értelmezéséhez. A javítást a docker compose config paranccsal ellenőrizd.

11. Több szolgáltatás indítása

Platform: Debian VM – SSH terminál.

Indítsd a Compose-projektet háttérben, és ellenőrizd mindkét webszervert.

sudo docker compose up -d
sudo docker compose ps
curl -I http://localhost:8081
curl -I http://localhost:8082

12. Compose-projekt módosítása és leállítása

Platform: Debian VM – SSH terminál; YAML-szerkesztés.

Módosítsd a második szolgáltatás host portját 8082-ről 8083-ra. Alkalmazd a változást, ellenőrizd az új portot, majd állítsd le és távolítsd el a projekt konténereit.

Segítség: sudo docker compose up -d, curl -I http://localhost:8083, sudo docker compose logs --tail=10, sudo docker compose down.

IV. Azure Container Apps – saját Azure for Students előfizetés

Előfeltétel: aktív Azure for Students előfizetés, megfelelő jogosultság, és a választott régióban elérhető Azure Container Apps szolgáltatás. Az Azure Portal felülete változhat. A létrehozás előtt ellenőrizd az esetleges költségeket. A feladat nem igényel Azure Container Registryt.

13. Erőforráscsoport és Container Apps-környezet

Platform: Azure Portal – helyi böngésző, saját Azure for Students előfizetés.

Lépj be az Azure Portalra, válaszd a saját Azure for Students előfizetésedet. Hozz létre rg-container-lab-<azonosító> erőforráscsoportot, majd egy új Container App létrehozása során hozz létre egy Container Apps environmentet is, például env-container-lab-<azonosító> néven. Használj támogatott, az előfizetésedben engedélyezett régiót.

Segítség: Azure Portal → Container Apps → Create; Subscription, Resource group, Container Apps environment. A környezet létrehozása a Container App varázslójában is elvégezhető.

14. Nginx Container App telepítése

Platform: Azure Portal – helyi böngésző, saját Azure for Students előfizetés.

Hozz létre egy web-lab-<azonosító> nevű Container Appot a nyilvános nginx:stable image-ből. Engedélyezd az External ingress opciót, a target port legyen 80. A minimális replikaszám lehet 0, a maximális 1.

Segítség: Container image source: public registry / Docker Hub; image: nginx:stable; Ingress: External; Target port: 80. Az ingress HTTPS-végpontot biztosít, a konténer belső portja ettől még 80.

15. Ellenőrzés és takarítás

Platform: Azure Portal – helyi böngésző; opcionálisan helyi PowerShell curl.exe az URL ellenőrzéséhez.

Tekintsd meg az alkalmazás állapotát, revízióit és – ha rendelkezésre állnak – naplóit az Azure Portalon. Ellenőrizd a HTTPS-címet. Ezután töröld a kizárólag ehhez a feladathoz létrehozott erőforráscsoportot, és várd meg a törlés befejeződését.

Segítség: Container App → Overview, Revisions, Log stream; Resource groups → a saját laborkörnyezeted erőforráscsoportja → Delete resource group. Más feladatokhoz tartozó erőforráscsoportot ne törölj.
